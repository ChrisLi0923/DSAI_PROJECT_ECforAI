# Exploratory capability diagnostic: fixed design

Written 30 October 2026 before inspecting new strategy outcomes. The user authorized one bounded diagnostic and launch, with no subsequent evolutionary search or new confirmatory run. Existing studies are preserved and all current search/validation material is development data.

Reference: the previously frozen ordered triple [rotate2, rotate1, original], stop after the first two valid answers agree, otherwise vote. All formats map to canonical option identities. Ignored invalid votes, lowest canonical-index ties and explicit all-invalid failure are inherited. The reference is not reselected. Original format and full-five voting remain controls.

Stage A uses compatible historical 512/489 caches first and exactly partitions reference errors into finite-bank selectable versus absent. Oracles are finite-bank selection bounds. Stage B fits shared conditional candidate scorers using search-only question-grouped five-fold CV, with L2 strength in [0.0001, .001, .01, .1], tie strongest regularization. Mean conditional log loss is trained only where a correct candidate is present, with all questions retained in accuracy. Candidate features contain per-format support, normalized votes, support pairs and support conditioned on other invalid outputs. They contain no labels, answer identity features, question IDs or text. Fixed smoothed per-format reliability log-odds supply a predefined cheap control.

Stage C uses 128/256/512/1000/1500 nested samples of the expanded search pool at five recorded seeds, all evaluated on the same reused validation pool. CV remains internal to each subset. Training fit and validation performance, paired vote differences, model coefficients, fold/group and subset identities are saved. Draw variation is distinct from whole-question conditional bootstrap intervals; neither estimates every evolutionary algorithm's learning curve.

Stage D uses three original-layout prompts fixed in diagnostic/prompts.py: principle-first, elimination, exact-content-first. Short explanations have exactly one explicit FINAL: X suffix, on its own line or at the end of a sentence. Content-first must have two lines and uniquely match normalized option text; one conventional displayed-letter prefix may be removed, recorded, and checked for agreement with both text and final letter. Conflicts and truncations are retained; no judge or answer-label repair. A fixed cap of 128 greedy new tokens applies to all three. The written pair selection rule ranks all three pairs by search accuracy of reference-three-plus-pair plurality, pair mean standalone accuracy, total requested tokens, then names. It selects two, not on oracle coverage. Before validation generation, freeze selected prompts, combinations and all selector coefficients. No validation labels enter fitting, regularization, strategy selection or combination construction. Expanded-bank validation uses only common strategies and exact bank labels.

Stage E samples 300 search questions uniformly, joins fact1 from the pinned additional configuration by ID with content equality, and compares cached original/no-evidence with supporting/unrelated facts under identical wrapper and eight-token decoding. Decoy sources belong only to search, are different IDs and normalized facts, exclude literal complete-option overlap and high lexical fact overlap, minimize word-length difference and use seeded ties. This is approximate irrelevance/length matching, not guaranteed semantic independence. No answer/grading/rationale-derived text enters the prompt. Supporting facts are privileged evidence; their usefulness does not establish a retriever, and failure does not establish inability to reason.

Stage F repeats 64 historical singleton original requests with byte-identical messages and recorded decoding. Repeat execution keys differ deliberately while request identities match. Compare canonical, correctness, invalid and raw hashes. Review up to six uniformly seeded examples per four categories (about 24), without post-hoc causal claims.

Budget: 11082 planned new singleton calls under the verified complete initial matrix; smoke requests belong to these jobs. Every raw response preserves exact request identity, revision, instruction, decoding, tokens, time, truncation and parse status. Historical import costs remain separate. Locks, source/config/manifest/package freeze, durable attempts and per-response commits enforce safe resume. Reserve 1000 unused questions before selecting additions and never query/score them or use their facts as decoys. Reading source data for exclusion/joining is not inference. Duplicate checks cannot rule out paraphrases/pretraining exposure.

Whole-question paired bootstrap: 2000 replicates, seed301036; fitted selectors fixed; no candidate-row or draw-question independence assumption. Report draw variation separately and achieved calls/tokens with every accuracy. A 0.5-percentage-point practical-gain screen drives descriptive decisions (aggregation, strategy, retrieval, development size); it is not a significance test on reused validation. All comparisons and limitations appear whether positive or negative. Stop after the diagnostic report and decision table.

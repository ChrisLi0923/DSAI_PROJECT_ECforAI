## Representation and common evolution

Inherited binary query trees have depth <=5, <=15 query nodes and <=5 calls, with no repeated format on any path. Null children are stop actions. The same predicates, canonical voting, constraint repair, initialization, every-fourth-offspring subtree crossover, rank/hash tournament and nondominated accuracy/call survival with crowding are retained. This is NSGA-II-style selection, not a claim of a faithful reference implementation. Node count is a bound, not a third objective.

Five matched seeds: 11,29,47,71,101; population 32. Shared initial populations contain five singles, the original agreement policy and full-five voting, plus the same seeded random trees. All four evolutionary conditions use these identical populations per seed. Utility hill climbing receives the same initialization but follows a single incumbent, without crossover or population survival. The finite evaluation budget, rather than a fixed generation count, ends search; methods can therefore have different offspring/generation counts.

## Variants

G0 is the original ordinary mutation distribution over all tree sites. G3 is the original complementary-error mutation distribution and its documented global search-failure fallback. Their formats, operation choices and random-number behavior are regression-checked against the inherited operators. G3's failure statistics reuse the already charged base-policy predictions/visits, avoiding an unnecessary identical replay while retaining exactly the original rescue weights and choices.

G1 changes the location sampling of ordinary random mutation: choose uniformly among sites reached by at least one search question at the current post-crossover policy. Both query nodes and extendible stop sites are eligible. Terminal sites at depth five are omitted because no legal distinct query extension exists. G2 uses exactly the same active-site sampling rule. Zero visits means unobserved in finite search data, not logically unreachable. No branch is deleted on the basis of a zero visit count; only inherited depth/size/no-repetition repair may alter it when an edit creates a constraint conflict.

G2 constructs at most eight distinct legal complete trial policies at the chosen active site. First include every change to another path-unused query format, or each one-query extension at a stop site; include stopping at a non-root query node where legal. Root stopping without any observation is illegal. Then include one seeded random-subtree proposal and shuffled predicate changes up to the bound. Duplicated/unchanged trees are omitted; every scored trial is still charged even when another search step evaluated an identical policy. Candidate-pool truncation gives required format and stop edits priority. A final budget-limited step can score fewer trials and records the actual count.

Replay every trial on the entire SEARCH pool, with U = final accuracy - 0.01 * mean calls. The coefficient is a frozen preference, not a measured optimum. Exact utility comparisons use integer numerator 100*number_correct - total_calls, divided by 100*N. A correct individual response receives no special credit if the full-policy answer stays wrong. Choose maximum U, then lower total calls, smaller tree size, and lexicographic policy SHA256. With probability 0.20 choose uniformly from the scored legal trial pool instead, allowing exploratory and potentially harmful moves; the best trial is also allowed to be worse than the base. The exploration setting is fixed before final inference. If no distinct legal trial can be built, use a logged ordinary random mutation at the same active site with reason no_legal_distinct_trial_edits. No global error statistics are substituted for state-specific utility guidance. G3 deliberately retains its original global fallback as the legacy ablation, reported separately from random fallback.

G2 changes the proposal mechanism in two linked ways relative to G1: bounded format/stop/predicate/subtree trial construction and utility ranking, whereas G1 retains the original random proposal distribution at active locations. Thus G2 versus G1 evaluates the complete informed proposal mechanism, not utility ranking alone under an otherwise identical trial-pool distribution. G1 versus G0 primarily isolates observed/legal-location sampling. This unavoidable distribution difference is disclosed; no additional conditions are added after test inspection.

The utility hill-climbing control uses the SAME active-site rule, trial generator, complete-policy scorer, exact utility and tie rules as G2. It starts at the highest-utility shared initial candidate and accepts a trial only if its deterministic utility/cost/size/hash rank improves. After eight stagnant steps it restarts from a seeded choice among shared initial trees. It has no 20% worse-move exploration or crossover; this distinction defines the local-improvement control. All scored probes and base replays consume the same budget.

## Fair accounting and resume

Every condition/seed, including hill climbing, has 4,096 full-search-policy evaluation equivalents. Each scored initial, base, trial or terminal budget-audit replay is charged one unit, including duplicates and discarded trials. Each unit replays all 512 search questions; total question-policy replays therefore equal raw scored evaluations times 512. Visitation masks and final predictions/calls are produced in the same pass, so they are not hidden uncharged replays. Labels are used only outside that label-free pass. Base replays allow comparing mutation effects after crossover and are charged consistently. G3 rescue weights reuse that scored base result; arithmetic over these stored predictions is not a new replay.

Discarded G2 probes do not enter the validation candidate archive. The archive contains shared initial policies and selected offspring, matching the legacy archive concept. Hill climbing archives its initial pool and accepted moves. Raw scored candidate hashes, roles, trial scores and number of accepted offspring are all saved. Equal surviving-offspring counts are not described as equal compute. A single leftover budget unit is explicitly recorded as a remainder audit. Validation evaluations, baseline selection and post-search selected-policy diagnostics are measured separately and do not feed back into search. Diagnostic search replays after selection are explicitly counted in FROZEN.json; no trial scoring is hidden there.

SQLite commits each completed scored result under a deterministic step/role key, with policy hash, prediction/call arrays, base-node visit masks, utility and timing. Pending offspring plans, post-proposal RNG state, population, pending children and budget counts are durable. Resume reuses completed scores and continues the same trial plan, preserving counted records and random choices. Attempt rows expose interrupted unknown work; such overhead can exceed completed nominal units. Configuration/data/source/package drift is refused. Concurrent runs are refused with a lock. Finishing on a partial offspring generation is logged separately; standard survival is applied to the completed partial batch.

## Evolution and feedback: what should the operator search?

Evolutionary LLM research operates on several representations. EvoPrompt [1] and Promptbreeder [2] evolve instruction text; the latter also evolves mutation prompts. OPRO [10] uses scored histories to propose improvements, while EvoLLM [3] investigates in-context optimization operators themselves. EoH [4] evolves heuristic ideas and executable programs, Eureka [6] evolves reward code, and ADAS [7] searches agent programs. Model-merging evolution [8] changes model composition rather than query behavior. The survey [9] situates both EA-enhanced LLMs and LLM-enhanced EAs. Together these establish that an evolutionary wrapper alone is insufficient as a contribution: the useful question is what information the operator exploits and whether that improves search under controlled budgets.

GEPA [5] is a particularly relevant warning against broad novelty claims: it uses feedback from trajectories and combines complementary lessons across candidate lineages. TextGrad [13] likewise exploits richer feedback than a scalar score. DSPy [11] and MIPRO [12] optimize compound LM programs, exposing credit assignment and validation-selection questions. Their representations and feedback costs are much broader than this project's compact trees. Our narrow candidate contribution is a rescue-count distribution for choosing a presentation at a mutation site, compared with uniform random mutation using identical executable representation and evaluated-candidate budgets. It uses search labels only and does not ask an LLM to invent a prompt. It should be described as an ablation of a practical integration of existing ideas, not a new general optimizer or a GEPA reproduction.

Strength: targeted feedback could reduce unproductive format proposals. Limitation: rescue of a wrong terminal prediction does not guarantee that adding the response changes a majority vote, and correlated mistakes may persist. State-specific counts can be noisy, so the fallback is declared rather than tuned using validation outcomes. Greedy construction receives the same search statistics, testing whether evolution adds anything beyond local construction.

## Presentation sensitivity, response contracts, and ensemble diversity

Sclar et al. [14] show that apparently superficial formatting choices can affect model performance and introduce FormatSpread. Wang et al. [15] distinguish generated text answers from first-token likelihood evaluation for multiple-choice robustness. These findings motivate a small fixed pool, exact preservation of option text, canonical identity remapping, and an explicit parser. This experiment evaluates generated letters; it does not infer that a first-token evaluation would behave identically.

MoA [18] aggregates model outputs in layers, whereas Self-MoA [19] cautions that adding different models can sacrifice source quality even while increasing diversity. Soft self-consistency [20] considers score-based selection when exact answer matches are sparse. Their common lesson is that raw diversity is not equivalent to useful accuracy gain. The exploratory pilot's oracle coverage indicates only the existence of correct answers in the pool; it is not implementable without labels. Fixed-subset enumeration and single-format selection are therefore essential controls. Our four-option canonical answers make plurality voting natural, without extra LLM aggregation calls or probability features. No claim is made that format diversity is equivalent to model diversity.

Strength: equivalent presentations isolate a reproducible source of disagreement within one frozen model. Limits: a finite pool can miss other useful perturbations, rotations may alter behavior despite preserving intended semantics, and all simple ensembles can fail together. Oracle coverage is only an upper bound and cannot be a deployment comparator.

## Adaptive computation and cost: why stopping is already established

RouteLLM [16] learns model routing from preference data. RouterBench [17] makes cached inference outcomes useful for systematic routing evaluation. Snell et al. [21] emphasize that effective test-time computation depends on problem difficulty. ReASC [22] extends count-based adaptive sampling using response reliability. The older Adaptive-Consistency and FrugalGPT papers (below) directly establish agreement stopping and learned cascades before this project. Consequently neither adaptive allocation nor cheap early exit is novel here.

This project restricts observations to queried canonical predictions, vote counts, invalid indicators, queried formats and remaining calls. It uses no learned confidence estimator, hidden-state features, reference answer at inference, or access to unqueried predictions. This makes policy behavior auditable but can limit headroom relative to richer routers. Equal call caps do not imply equal tokens or latency: formatting changes input length, batching changes execution, and generated responses can vary with execution context. We separately report matrix-generation work, CPU search, requested deployment tokens/calls, and a small measured live sample. A cached matrix can support reproducible policy comparisons but cannot establish a production latency improvement.

## Research gap and falsifiable assessment

A modest, testable opportunity is whether search-only error complementarity helps an evolutionary operator discover compact presentation policies that retain accuracy with fewer requested calls. The controlled comparison is guided versus uniform mutation over five search seeds at predeclared validation cost caps. The stronger practical question is whether either beats greedy and validation-selected fixed subsets at the achieved final costs. Failure on either comparison is retained. Existing work makes publication-level novelty uncertain; this review motivates a course-project contribution and explicitly does not establish a first-in-literature claim.
